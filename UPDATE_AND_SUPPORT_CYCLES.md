# Update and Support Cycles

This document defines how reusable systems should be updated and supported across memberships, affiliate systems, content variants, and product variants in the wider `lippytm` ecosystem.

## Purpose
Keep reusable systems valuable over time by making support, refresh, review, and maintenance part of the product and distribution model.

## Core Principle
A reusable system should not end at launch. It should have a visible cycle for support, improvement, review, and refresh.

## Cycle Types

### 1. Content Refresh Cycle
Use for:
- lesson updates
- article updates
- public demo refreshes
- audience-specific revisions

### 2. Product Support Cycle
Use for:
- setup fixes
- support-note improvements
- template corrections
- bundle improvements

### 3. Membership Update Cycle
Use for:
- recurring member resources
- new lesson drops
- revised learning paths
- improved support materials

### 4. Affiliate Support Cycle
Use for:
- campaign refreshes
- updated partner materials
- revised product notes
- audience-specific support improvements

## Best Practices
- keep update notes visible
- separate urgent fixes from planned refreshes
- connect support changes back to the base system when useful
- include review and security notes in update cycles
- archive outdated variants instead of letting them confuse active users
